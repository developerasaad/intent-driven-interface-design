# Reference boundaries

Read only when the task includes inspirations, screenshots, reference websites, existing component systems, or other UI skills that could steer the output.

## First establish the reference's authority

- **Exact reproduction or existing brand system:** follow the requested fidelity and scope. Note missing assets or uncertain details rather than silently inventing them.
- **Functional model or design precedent:** analyze what behavior or structure succeeds and why; choose presentation independently.
- **Loose inspiration or another skill:** treat as optional evidence, not permission to replicate the source's signature look.
- **Conflicting references:** identify underlying common needs; resolve conflicts using the present project's goals. Clarify only a conflict that materially changes deliverables.

## Separate the dimensions

For each relevant reference, distinguish:

| Dimension | Questions to extract | What not to assume |
| --- | --- | --- |
| Task support | Which user action is made easier? | That its visual form is required |
| Information architecture | What comes first, what is grouped, what is discoverable? | That its section order suits this product |
| Interaction | What feedback, navigation, or affordance is effective? | That interaction and appearance must travel together |
| Visual system | What rules create internal consistency? | That its font, palette, geometry, and ornament should be adopted |
| Identity | Whose personality or brand does it express? | That another brand's voice belongs here |

## Anti-capture checks

A design may be too dependent on a reference when its visual hierarchy, section rhythm, components, decorative treatment, and typography are all similar without a project-specific reason. If that happens, revisit the content and design contract rather than applying superficial changes such as swapping colors.

Do not turn this into a simplistic similarity prohibition: conventional patterns are often best, and users may explicitly want consistent styling with an existing brand. The problem is **unjustified transfer of distinctive decisions**.

When several existing skills are active, use their factual domain knowledge and tool workflows. Resolve aesthetic prescriptions in favor of the user's brief and the current design contract. Never make a broad claim that another skill was read or applied if it was not accessible.
